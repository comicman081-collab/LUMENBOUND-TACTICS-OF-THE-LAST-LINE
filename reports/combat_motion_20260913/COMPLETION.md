# 전투 동작 및 정찰몹 개별 생존 수정 — 2026-09-13

- 기존 동료 CHR001–CHR008: 기본 공격·일반 스킬·궁극기마다 6개의 실제 자세, 총 144프레임을 새로 제작했다. 기존 적 ENM001–ENM003 및 BOSS001: 기본 공격·일반 스킬 48프레임을 제작했다. 합계 32동작 / 192프레임이다.
- 승인된 SD 원본의 얼굴·머리·장비·무기를 참조한 Sprite Gen GPT Codex 정식 생성/추출/검수 경로를 사용했다. 하나의 서 있는 그림을 회전시켜 만든 공격 애니메이션으로 대체하지 않았다. 초록 배경 원본과 별도 투명 런타임 파생본을 보존했다.
- 준비→실제 발사/타격→후속 동작→회복을 전투 시간에 연결했다. 방패/검/소총/연사/포격/마법/치유/발톱/보스 포격에 다른 궤적·발사·충돌 표시를 적용했다. 궁극기의 투사체 도착도 피해 표시 시점과 맞췄다.
- 동료의 평상시 위치는 왼쪽 다섯 열의 아래·위·아래·위·아래 배치로 유지된다. 근접 공격 때만 목표 쪽으로 전진하고 자기 자리로 돌아간다. 피격 반응, 기존 SD 전투불능 그림, 적 폭발은 유지한다.
- 전투에 필요한 새 동작 페이지만 로드하며 디코딩된 페이지 캐시는 32MiB 상한을 적용한다.

## 정찰 1-1을 처치하면 1-2도 사라지던 원인

맵 모델의 처치 기록은 이미 `node_id`별로 분리되어 있었지만, 화면의 `_node_encounter_cleared`와 선택·이동 종료·경로 차단 코드가 여전히 `stage_stars`를 함께 검사했다. 정찰몹들이 같은 스테이지 전투 데이터를 공유하므로, 한 번 승리하면 생존한 다른 몹의 그림도 제거되고 선택/전투 진입이 막혔다.

화면과 접촉 판정은 개별 조우의 처치 기록을 사용하도록 통일했다. 캠페인 별점·보상 기록과 기존 저장본 마이그레이션은 유지한다. 살아 있는 정찰몹과 본대는 각자의 승리가 필요하다. 다음 조우 안내 역시 아직 처치하지 않은 본대를 건너뛰지 않는다.

수정 전 실제 브라우저에서 **1-1 승리 → 1-2 논리 생존 → 1-2 그림 제거**를 재현했다. 검사 기록은 `scout_browser_before/`에 있다. 검사 도구의 잘못된 타이틀 복귀 가정으로 중단된 중간 기록도 `scout_browser_navigation_fixture/`에 별도로 남겼다.

- 빌드의 이름/VERSION과 최종 PCK 해시 일치를 내보내기 종료 시 확인하도록 강화했다. 최종 PCK 해시는 실행 서버에서도 일치했다.

검사는 로컬의 격리된 저장본으로 수행했다. 사용자 저장본을 초기화하거나 원격 배포하지 않았다.
