# 성장 화면 디자인 기준

Web Design Engineer: 프로젝트 ON / STANDARD. 기존 Godot UI를 유지하는 Redesign · Preserve.

사용자: 획득한 재화를 어디에 써야 할지 바로 이해해야 하는 모바일 RPG 이용자.
시각 언어: 기존 짙은 남색 전술 UI, 민트색 실행 버튼, 금색 성장 목표. 기존 한글 폰트와 실제 캐릭터/스킬 아이콘 유지.

- 변형 2: 안정된 열 너비, 한 줄 캐릭터 선택, 동일한 4개 성장 탭.
- 움직임 1: 선택·실행 결과만 즉시 갱신. 장식 애니메이션 없음.
- 정보 밀도 7: 한 카드에 현재/이후 효과, 보유/필요 비용, 불가 이유와 실제 실행을 함께 표시.
- 에셋 의존 3: 스킬 아이콘은 기존 원본 사용. 큰 초상화는 정보 탭으로 이동.
- 정체성 보존 9: 기존 토큰·경로·저장 구조·성장 수치·합류 조건 유지.

보호: GROWTH/CHARACTER_DETAIL 진입, 보상 후보 진입, 실제 서비스 검증, 공유 재화 정확 차감, 장비선택, 화면 회전, TouchProgressionScroll, 기존 스킬 아이콘. 노출된 DEV 선물 버튼은 공개 성장 UI에서 제거.
개선: 좁게 접히던 버튼 열은 실제 가용 너비를 균등 사용. 선택 상태와 사용 불가 상태를 구별. 카드 안쪽 여백과 스킬 아이콘은 고정 논리 픽셀이 아닌 기존 반응형 배율 사용.
최대 위험: 보이는 강화 예상과 실제 효과/차감/저장의 불일치. Ponytail FULL 검토와 기존 실제 브라우저 터치·새로고침 검증으로 확인한다. 생성 이미지·외부 서비스·스택 교체는 사용하지 않는다.

브라우저 검증은 앞서 사용자 요청한 FULL 검증/반복 화면 수정의 진행 중 실행 검증을 이어간다. 코드 PASS를 브라우저 PASS로 대체하지 않는다. 최종 실행 결과는 별도 acceptance.json에 기록한다.
