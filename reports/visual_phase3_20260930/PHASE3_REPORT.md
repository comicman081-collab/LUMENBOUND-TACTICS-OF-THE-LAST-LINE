# 로딩 문제 수정 + 필드 연출 시스템 3단계 (2026-09-30)

요청: "로딩 문제 해결하고 3단계 진행해라."

- 방향 문서: `reports/visual_direction_20260930/VISUAL_DIRECTION.md`의 3단계(C3 필드 연출 시스템).
- 모든 연출은 화면 표현이다. 지도 규칙, 전투 계산, 보상, 저장은 건드리지 않았다.
- 참고 영상의 그림이나 UI는 가져오지 않았다. 말풍선, 감정 표시, 배너, 레터박스는 모두 코드로 그렸다.

## 1. 로딩 문제 (첫 지도 진입 "TACTICAL MAP UNAVAILABLE")

### 증상

웹에서 처음 지도에 들어갈 때 프레임이 느리거나 탭이 가려져 있으면 "TACTICAL MAP UNAVAILABLE"로 멈췄다.
r16을 Chrome CPU ×16으로 제한하면 `STAGE_ENTRY_PRELOAD_TIMEOUT map=CH01_MAP phase=map_ready elapsed_ms=45094`가 재현됐다.

### 원인

| 원인 | 설명 |
|---|---|
| 벽시계 감시 | 12초 무진행 / 45초 전체 제한을 실제 시간으로 쟀다. 그려지지 않는 동안에도 시간이 흘렀다 |
| 고정 작업 조각 | 프레임마다 고정 10ms만 일해서, 3초짜리 빌드가 프레임 수백 개를 요구했다 |
| 진행 표시가 드문 구간 | 지도 빌드는 진행 지점이 6곳뿐이다. 그 사이(특히 세계 구성 `_build_world`의 타일 스캔)는 호출마다 프레임을 하나씩 썼고, 진행 표시가 없어서 초당 2~4프레임이면 12초 무진행 제한에 걸렸다 |

### 수정

- `core/loading_clock.gd` (새 파일): 전달된 프레임 한 번에 최대 250ms만 센다. 작업 조각은 측정한 프레임 간격의 절반(20ms~250ms)으로 잡는다.
  맵 빌더, `StageAssetCache` 웜업, `app_shell`의 지도·전투 감시가 같이 쓴다.
- `chapter_map_screen.gd` `_finish_web_build_slice`:
  - 조각 예산 건너뛰기를 상세 빌드(`web_stage_entry_preload_active`)뿐 아니라 `map_ready` 전체(`not map_ready_complete`)에 적용했다. 세계 구성도 같은 방식으로 진행한다.
  - 프레임을 한 번 넘긴 조각은 마지막 진행 지점을 다시 알려 무진행 시계를 되돌린다(하트비트). 전체 45초 제한은 그대로 남는다.
- `StageAssetCache` 웜업과 `web_soak_probe`에 같은 시계·조각을 적용했고, 대기 셰이더를 부팅 웜업에 넣었다.

### 실제 브라우저 검증 (Chrome headless + CDP 구동기, 매번 새 프로필)

| 빌드 | 제한 없음 | CPU ×16 | 프레임 2/초 | 프레임 4/초 |
|---|---|---|---|---|
| r16 | 약 4.2초 | **TIMEOUT 45.1초** | - | - |
| r17 (시계·조각만) | 3.9초 | 완료 34.4초 | **TIMEOUT 26.5초** | **TIMEOUT 13.5초** |
| r18 (상세 빌드 이후에만 하트비트) | - | - | **TIMEOUT 26.3초** | **TIMEOUT 13.5초** |
| **r19 (최종)** | **2.15초** | 완료 36.9초 | **완료 25.0초** | **완료 13.4초** |

- r18의 타임아웃은 개발 빌드(개발자 모드 진단 출력 `WEB_FRAME_GAP infill_scan` 253ms가 프레임마다 반복)로 원인을 찾았다. 진행 표시 없는 세계 구성 구간이었다.
- 프레임 1/초는 측정하지 못했다. 구동기의 고정 클릭 타이밍이 그 속도에서는 맞지 않아 지도까지 가지 못했다.
- 전투 진입의 느린 프레임 동작은 이번에 재지 않았다. 전투 감시는 작업 단계마다 진행 표시를 하므로 같은 빈틈은 없는 것으로 읽었다.
- 새 테스트 `res://tests/loading_pacing_runner.tscn` 34/34 (시계 상한, 숨은 탭, 느린 프레임 30개, 에셋 웜업, 소스 지점 검사).

## 2. 필드 연출 시스템 (C3)

### 구조

| 조각 | 역할 | 파일 |
|---|---|---|
| 스크립트 형식 | 명령 딕셔너리 배열. `"with": true`는 앞 명령과 같이 시작. 검증, 라이브러리, 토큰 채우기 | `field/field_script.gd` |
| 실행기 | 시간 구동 `FieldScene` (`advance`, `tap`, `skip`, `snapshot`) | `field/field_scene.gd` |
| 화면 | `FieldSceneOverlay`: 말풍선(타자 효과), 감정 표시, 배너, 레터박스, 건너뛰기 버튼, 탭·Enter·Space | `field/field_scene_overlay.gd` |
| 호스트 어댑터 | `FieldStage` 인터페이스 + 지도용 / 전투용 | `field/field_stage.gd`, `map_field_stage.gd`, `battle_field_stage.gd` |
| 라이브러리 | 장면 25개, 보스 후일담 바인딩 | `data/field_scenes/field_scenes.json` |

명령: `say`(말풍선, 아군 청록·적 빨강·이벤트 금색), `move`, `face`, `jump`, `emote`(!, ?, 땀, 분노, 섬광), `camera`(focus / shake / zoom), `banner`, `sfx`, `wait`.
배역: `leader`, `ally`, `foe`, `boss`, `event`, `center`(내레이션 기준점).

### 쓰는 곳

| 장면 | 동작 |
|---|---|
| 맵 이벤트 접촉 | 기존 `event_encounters` 쪽지를 장면으로 바꾼다(`from_dialogue_pages`): 카메라가 이벤트 폰으로 밀고 들어가고, 서로 마주 보고, "!" 와 작은 도약, 금속 타격음, 제목 배너, 쪽지마다 말풍선(이름·초상), 결과 배너 |
| 보스 대치 | 같은 변환. 적 말풍선은 빨강이고 보스는 더 세게 밀고 들어가며(zoom 1.45), 무거운 타격음을 쓴다 |
| 보스 후일담 | 보스를 쓰러뜨린 뒤 결과 카드 전에 짧은 장면: 보스가 있던 자리에 마지막 말 1줄, 아군 답 1줄. 23개 보스 전투(CH01~CH20 N20, CH01~03 H05)에 각각 글을 새로 썼다 |

- 대사 원문은 기존 스토리 데이터를 그대로 쓴다. 새로 쓴 것은 후일담 글뿐이다(적은 기계라 대명사 없이 썼다).
- 긴 대화와 감정 장면은 그대로 비주얼 노벨 화면에서 한다. 필드 장면은 짧게만 쓴다.
- "전환 줄이기" 설정이나 건너뛰기 진행 중에는 기존 읽기 패널 경로(이벤트·보스)로 돌아가고, 후일담은 건너뛴다.
  지도에 적 폰이 없을 때도 기존 경로로 돌아간다.
- `battle_view.field_aftermath_enabled`는 기본 false다. 테스트와 도구는 탭을 기다리지 않고, 호스트(`app_shell`)만 켠다.

### 호스트에 넣은 것

- `chapter_map_screen.gd`: `field_*` 훅(폰 위치·도약·좌우, 적 폰 위치, 카메라 포커스·줌·흔들림, 해제). 웹 앞 오버레이 폰에도 같은 위치·도약을 더한다. 장면 중에는 노드 이름표를 숨긴다.
- `battle_view.gd`: 보스 후일담 재생과 대기(`_field_aftermath_holds`), 유닛 위치·도약·카메라 훅. 죽은 적은 그려지지 않으므로 후일담 말풍선은 보스가 마지막에 있던 자리에 뜬다.
- `app_shell.gd`: `_play_field_contact`, `_map_node_id_for_stage`, 전투 화면 설정 두 줄. 이벤트·보스 접촉이 필드 장면을 먼저 시도하고 실패하면 읽기 패널로 간다.

## 5. 알려진 점과 하지 않은 것

- 필드 장면은 실제 브라우저(웹 빌드)에서 돌려 보지 못했다. 창 있는 원본 셸 캡처와 헤드리스 테스트로만 확인했다. 웹 전용 분기는 앞 오버레이 폰 위치 계산 한 줄이다.
  접촉 장면을 만들려면 저장을 채우거나 진행해야 해서 이번 구동기로는 닿지 못했다.
- 프레임 1/초 이하의 첫 진입은 재 보지 못했다.
- 보스 후일담은 보스 전투(23개)에만 있다. 일반 전투에는 넣지 않았다.
- 효과음은 게임에 있는 전투 효과음(타격·충돌)만 쓴다. 전용 UI 소리는 없다.
- 하지 않은 것: 더 많은 맵 이벤트 전용 연출 스크립트(지금은 기존 쪽지 변환), 장면 편집 도구.
- 배포·푸시는 하지 않았다.
