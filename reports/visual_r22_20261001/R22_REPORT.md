# r22 (2026-10-01)

요청: "r21 버전으로 우선 배포는 했다. 개선, 추가, 버그 수정 등 할게 있는지 확인하고 r22 버전으로 업데이트 해라."
같이 받은 요청 두 가지:

- "지금 고저차가 있는 맵과 이동 가능한 영역을 표시해주는 노란 박스의 높이가 잘 안맞아서 좀 이상하니 그것도 같이 수정해서 진행해라."
- 타이틀 라이브 2D 시안 영상(`title_live2d_preview.mp4`)을 보고: "너도 이런 수준으로 타이틀 화면 라이브 2d 적용해서 만들어야 한다."

원칙:

- 모든 변경은 화면 표현이다. 지도 규칙, 전투 계산(30Hz 결정적 시뮬레이션), 난수, 보상, 저장은 건드리지 않았다.
- 참고 영상의 그림이나 UI는 가져오지 않았다. 타이틀 퍼핏은 이 프로젝트의 기존 인물 일러스트를 그대로 쓴다.
- **배포·푸시는 하지 않았다.** r22는 Codex가 Sites에 올린다(인계 사항은 6장).

## 2. 지도: 이동 범위 노란 박스 높이

원인(`chapter_map/runtime/world_cell_overlay.gdshader` 머리말 참고):
- 이동 범위·경로·격자는 CPU가 한 번 투영한 뒤 Control 하나로 통째로 밀어서 움직이고 있었다. 통째로 미는 방식은 직교 카메라에서만 맞는다.
- 원근 카메라에서는 높이와 깊이마다 이동량이 다르다. 그래서 카메라를 옮기거나 줌하거나 카메라 연출이 나올 때 노란 칸이 지형에서 미끄러졌다.
  높은 고원에서 가장 심했고, 격자는 절벽 위에서 최대 약 40px까지 어긋났다.

고친 방식:
- 칸을 월드 좌표(칸 자신의 윗면 높이)로 두고, 버텍스 셰이더가 지도 카메라의 투영 행렬로 그린다(`world_cell_overlay.gd/.gdshader`).
  카메라가 움직이면 행렬 하나만 올리고 다시 만들지 않는다. 직교·원근 어느 쪽이든, 카메라 연출·흔들림 중에도 맞는다.
- 칸 채우기는 인접 칸과의 경계에 가는 이음선만, 범위 바깥 테두리는 월드 폭을 가진 띠(3D 범위의 굵은 테두리와 같은 모양, 모서리는 마이터 접합)로 그린다.
- 경로선과 선택 고리도 같은 투영을 쓴다(점 몇 개만 다시 투영). 격자는 덩어리로 나눠 카메라 앞·시야 근처 것만, 가까운 것부터 프레임당 몇 개씩 만든다.
- 웹 전용 경로다. 데스크톱은 `LUMEN_MAP_PROJECTED_OVERLAY=1`로 같은 경로를 돌려 3D 버전과 비교할 수 있다.

검증:
- `tests/map_overlay_projection_runner`(1·7·15장, 원근·직교 각각, 189건): 셰이더가 쓰는 투영 행렬이 `Camera3D.unproject_position()`과 0.05px 이내로 같고,
  칸 높이 오차 0.0001 이내, 범위 바깥 테두리와 띠의 폭·접합이 맞고, 카메라 이동·줌·카메라 연출 뒤에도 경로선·선택 고리가 0.05px 이내로 따라간다.
  데스크톱(3D) 경로가 여전히 3D 메시를 쓰는지도 확인한다.
- 지도 테스트(`chapter_map/tests/map_test_runner`) 358/358. 소스 문자열을 보던 검사 한 줄은 새 구조에 맞게 갱신했다.
- 웹(Chrome headless, 1280x720)에서 이동 범위를 띄워 캡처했다. 노란 테두리가 칸마다 자기 윗면 높이에 붙는다(`screenshots/web_map_overlay.png`).

## 3. 타이틀 라이브 2D

만든 것(`ui/title_live2d.gd`, `title_live2d_rig.gd`, `ui/shaders/title_puppet.gdshader`, `title_halo.gdshader`, 자산 `assets/title_live2d/`):
- 영상으로 바꾸거나 뼈대를 심지 않았다. 기존 일러스트(CHR001, CHR002)를 그대로 두고 픽셀마다 역변환으로 휘게 한다(Catmull-Rom 샘플링).
- 마스크 두 장이 부위를 정한다. 마스크 A는 머리카락 가닥, 마스크 B는 옷·발광·장식이다.
- 움직임: 숨쉬기, 눈 깜박임(겹깜박임 포함), 시선 이동, 머리 기울임, 용수철-질점 모델의 머리카락·옷 흔들림, 랜턴의 진자 운동(별도 층, 이음선 722~740행),
  모두가 공유하는 심장박동(2.6초), 입장 연출(순서대로 들어오는 안무), 마우스·터치 시선 따라가기.
- 품질 단계: 프레임 시간 75번째 백분위가 26ms를 넘으면 한 단계 낮추고, 18.5ms 아래가 3번 이어지면 올린다. `fx2.w`로 셰이더가 단계별로 일을 줄인다.
- 자산은 `runtime_web` 밖(`assets/title_live2d/`)에 둔다. `runtime_web`의 PNG는 가져오기 설정이 손실 WebP로 고정돼 있는데, 마스크는 색 채널을 섞는 압축을 쓰면 안 되기 때문이다.
  히어로·랜턴은 무손실, 마스크 A는 밉맵 없음.
- 실제 렌더러나 자산이 없으면 `TitleLive2D.attach()`가 null을 돌려주고, 호출한 쪽이 기존 정지 타이틀 그림을 그대로 쓴다.
- 웹 예열 단계(`autoload/web_soak_probe.gd`)에 `타이틀 연출` 조각을 넣어, 인트로가 끝난 뒤 셰이더 컴파일로 화면이 멈추지 않게 했다. 지도용 투영 셰이더 예열 조각도 같이 넣었다.

검증:
- 데스크톱 창 캡처(`tools/capture_title_live2d_qa`): 중립·입장·정착 상태 정지 화면과 14초 영상.
- 웹(Chrome headless, 데스크톱 1280x720과 휴대폰 가로)에서 타이틀이 실제로 움직이는 것을 캡처(`screenshots/web_title_*.png`).
- 시안 영상: `title_live2d_r22_preview.mp4`(이 폴더, 7.6MB, git 제외).

## 4. r21 점검에서 찾아 고친 것

### 4.1 전투 웹 프레임

웹의 GLES3 캔버스 렌더러는 `draw_polyline`, `draw_colored_polygon`, `draw_circle`, 굵은 `draw_line`마다 명령을 따로 만들고, 그때마다 GPU 버퍼(VAO/VBO)를 만들었다가 지운다.
r21 전투 화면은 이런 명령이 프레임마다 수백 개였다(바닥 장식만 최대 약 200개). r22는 이렇게 줄였다.

- `battle/view/battle_mesh_kit.gd`: 정적 `ArrayMesh`를 만들어 `draw_mesh`로 그린다(속 빈 사각형, 의도 다이얼 호, 그리드 격자 등).
- `battle/view/battle_soft_sprites.gd`: 부드러운 타원·고리를 캐시된 절차적 텍스처로 그린다(발밑 그림자·고리).
- `battle_region_floor.gd`: 지역 바닥 장식과 격자를 챕터·화면 크기당 한 번 쪼개 메시로 둔다. 천천히 도는 부분만 실시간 선으로 둔다.
- 상태 외곽선을 사각형 네 개로, 머리 위 기준점·자세·하강 자세를 한 `_draw()` 패스 안에서 캐시, 흔들림 모양을 상수 표로 바꿨다.
  유닛 상태 복사는 깊은 복사(모든 유닛을 매 프레임)에서 얕은 복사로, 지난 웨이브 기록은 살아 있는 것만 복사하게 했다.
- 측정(같은 PC, 매번 새 Chrome 프로필, r22/r21 번갈아 2회씩, Chrome headless를 CDP로 조작. 드라이버는 세션 임시 폴더에 있었고 저장소에는 넣지 않았다):

  | 구간 | r21 | r22 |
  |---|---|---|
  | 전투, CPU 제한 없음 | 21.8 / 20.4 fps | 41.7 / 41.0 fps |
  | 전투, CPU 4배 느림 | 6.4 / 5.2 fps | 10.9 / 10.2 fps |
  | 지도, CPU 제한 없음 | 60.3 / 60.4 fps | 60.3 / 60.2 fps |
  | 지도, CPU 4배 느림 | 27.5 / 25.0 fps | 28.0 / 25.8 fps |

- 한계: 전투 한 프레임에 폴리곤 명령이 아직 약 130개 남아 있다(VAO 생성·삭제). CPU 4배 느림에서 10fps대는 여전히 낮다.

### 4.2 버그

1. **피해 숫자 접두어(측면·엄폐·직격)가 네모로 나옴**: 둥근 숫자 서체에는 한글이 없고 웹에는 대체 시스템 글꼴이 없다. 전투 글꼴을 폴백으로 연결했다(`_bind_damage_font_fallback`).
2. **`▸`·`▾` 글리프**: 지도 미니맵 토글(`미니맵 ▸` / `▾`)과 필드 연출 건너뛰기(`건너뛰기 ▸`)가 웹 글꼴에 없는 글리프라 네모가 될 수 있어 `›`, `▼`로 바꿨다.
3. **마우스 오른쪽 클릭이나 휠이 연출을 건너뜀**: 필드 연출·인카운터 와이프·장식 타이틀 카드는 왼쪽 클릭과 터치만 받는다.
4. **보스 후일담 장면이 입력을 못 받음**: 셸의 레이아웃을 다시 짤 때 화면 전체를 덮는 전술 입력 층(STOP)이 후일담 장면 위에 다시 얹혀, 장면이 기다리는 탭을 전부 삼켰다. 장면을 맨 위에 유지한다.
5. **전투 뒤 지도의 카메라 연출 잔재**: 전투 전에 대기하던 카메라 연출·발견 연출이 남아, 전투에서 돌아온 뒤 첫 이동이 끝나면 옛 상자 쪽으로 카메라를 끌어당겼다. 지도로 돌아올 때(`resume_from_cache`) 비운다.
6. **다음 웨이브 표식 글씨 하한**: `NEXT WAVE ×N` 글씨가 작은 화면에서 9 CSS px 아래로 내려가지 않는다.
7. **유닛 이름 가독성**: 밝은 보도 타일 위에서 이름이 묻혀서 어두운 외곽선을 넣었다.
8. **MISS 숫자 정리**: 크기 0.72 → 0.60, 지속 1.15초 → 0.80초, 먼저 그려서 진짜 피해 숫자가 위에 오게 했다.
9. **랜드마크 연기 덩어리**: 애니메이션 대상이 아닌(먼) 건물에 꽉 찬 크기의 회색 마름모가 불 위에 앉아 있었다. 시작 크기를 줄였다.

  r21과의 비교는 4.1절에서 같은 시간대에 번갈아 잰 값만 근거로 삼는다.
- 휴대폰 가로 캡처(`screenshots/web_title_phone_landscape.png`)와 4.1절 비교는 직전 r22 빌드에서 찍었다(PCK는 아래의 이미지 격리 말고는 같다).

### Sites 용량 (Codex가 꼭 볼 것)

- Codex의 v22 배포 기록(`reports/sites_r21_intro_fix_20261001/deployment.json`): 압축 해제 tar 267,581,440바이트, 한도 256 MiB = 268,435,456바이트 → 여유 **854,016바이트**.
- 처음 만든 r22 PCK(179,593,696바이트)는 r21 PCK(176,855,796바이트)보다 2,737,900바이트 크다(대부분 타이틀 라이브 2D 텍스처 2.66MB). 그대로면 한도를 약 1.9MB 넘는다.
- 그래서 코드가 어디서도 참조하지 않는 옛 타이틀 이미지 `title_cast_plate_r1.png`, `title_cast_plate_portrait_r1.png`(PCK 안 ctex 2,526,818바이트)를 격리하고 다시 빌드했다.
  - 근거: 경로와 `uid://`를 프로젝트 전체에서 검색해도 `tests/test_runner.gd`(빌더 소스의 글자만 읽음), 빌더 `tools/art/build_title_cast_plate.py`, QA 기록 JSON뿐이다.
    로고 `title_logo_r1.png`는 `app_shell.gd`가 쓰므로 그대로 뒀다.
  - 직전 r22 PCK와 항목별로 비교하면 빠진 것은 이 이미지 2장의 ctex·import 4개뿐이고 `uid_cache.bin`이 125바이트 줄었다. 나머지 3,981개 항목은 해시까지 같다.
    그래서 직전 r22 빌드에서 한 회귀·웹 확인이 그대로 유효하고, 격리 뒤에도 전체 회귀를 다시 돌렸다(5장).
  - 격리 위치: `quarantine/title_cast_plate_superseded_20261001/`(원래 폴더 구조 그대로 파일 4개와 `MANIFEST.json`에 SHA-256·사유·복구 방법).
    같은 기록을 이 폴더의 `title_plate_retirement.json`에도 뒀다. 삭제하지 않았다. 복구는 파일을 `godot/assets/art/title/`에 되돌리거나 `python tools/art/build_title_cast_plate.py`로 다시 만든다.
- 새 PCK는 r21보다 210,076바이트만 크다. PCK 조각 수는 같은 43개이므로 압축 해제 tar는 약 267.80MB, 여유는 약 0.64MB로 추정한다. **실제 값은 Codex 도구로 만들어 봐야 안다.**
- 여유가 0.6MB뿐이라 에셋·음성을 더 넣으면 한도를 넘는다. 더 줄일 후보(건드리지 않음): `godot/data/battle_contact_anchors_r1.json` 2.2MB.
  런타임은 `battle_contact_anchors_r2_spritegen.json`만 읽지만, `tools/web_qa/write_continuation_validation_manifest.mjs`가 이 이름을 참조한다.

### Codex가 해야 할 일

1. **`godot/screens/command_presentation.gd`는 커밋하지 않았다.** 타이틀 연결 부분(`TitleLive2D` preload와 `title_backdrop`의 `live_cast` 분기,
   라이브 2D를 못 쓸 때만 정지 초상 두 장을 그리는 분기 포함)이 Codex의 미커밋 `title_backdrop(s, parent, intro_gate := false)` 재작성 안에 들어 있다. Codex가 타이틀 변경을 커밋할 때 같이 커밋해야 한다.
   r22 빌드에는 이 두 줄이 들어 있어 그대로 올려도 된다. 다만 이 파일이 커밋되기 전에는 저장소의 커밋만으로 다시 빌드하면 라이브 2D가 화면에 붙지 않는다.
2. Sites 정리와 배포는 Codex 도구로: `tools/web/prepare_sites_minimal.py <site_checkout> builds/web_visual_r22_release`.
   인트로 영상은 Codex의 `stage_sites_intro.py`가 배포 폴더에 넣는다(내 빌드 폴더에는 없다). `tools/web/compact_sites_voice.py`에는 r21 경로가 하드코딩돼 있다(음성은 r21과 같다).
3. 배포 뒤 볼 것: 부팅 때 `WEB_RENDER_WARMUP_COMPLETE`(이 PC 약 10~13초), 타이틀 퍼핏이 움직이는지, 지도 진입.
4. `git status`에 남는 Codex 작업 파일(`export_presets.cfg`, `cinematic_fx.gd`, `landscape.html`, `tools/web/*.py` 등)은 건드리지 않았고 커밋하지 않았다.

## 7. 하지 못한 것, 한계

- 실제 휴대폰으로는 확인하지 못했다. 데스크톱 Chrome headless의 휴대폰 가로 창 크기 에뮬레이션까지만 봤다.
- 새 셰이더(타이틀 퍼핏, 지도 투영)는 NVIDIA + ANGLE(D3D11)에서만 확인했다. 다른 GPU·드라이버는 보지 못했다.
- 피해 숫자 접두어 한글은 단위 테스트와 데스크톱 확인까지다. 웹 캡처에서 직접 본 것은 아니다.
- 보스 후일담 탭 문제는 헤드리스 테스트로만 확인했다.
- 직교 카메라 경로는 설정 화면에 켜는 스위치가 없다(`map_camera_perspective` 설정).
- 지도 첫 진입 시간은 CPU 6배 느림에서 10~19초로 편차가 커서 r21과 r22의 차이를 가려내지 못했다(r21 18.6/9.8초, r22 15.4/17.1초).
- 전투는 CPU 4배 느림에서 약 10.6fps. 남은 폴리곤 명령 약 130개가 다음 병목이다.
